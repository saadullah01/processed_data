This crash occurs very frequently on linux platform and is likely preventing the fuzzer jsoncpp_fuzzer from making much progress. Fixing this will allow more bugs to be found.

So i was digging into this to improve the Fuzzer , the frequent crash is due to

TL;DR skipBOM is assuming that you have at least 3 bytes available to read.

Here the program is assuming that there are 3 bytes available in the buffer, however when you use an input of size 4-6 bytes,  the first 4 bytes are used to generate builder._settings and the rest are sent to the reader->parse, now in this the skipBom() function is called and it tries to read outside the buffer and causes the overflow, 
Reproducing steps ->
1) Any 4 byte input
2) 5 byte input with 5th byte being equal to \xEF (as strncmp will break if 5th byte is not equal to \xEF)
3) 6 byte input with 5th and 6th byte being equal to \xEF \xBB

Possible fix -> Adding a check condition before comparing strings.

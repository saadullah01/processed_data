If the srcSize is 2^n + 1, then ZSTD_adjustCParams() will give a window log of n, which means that the source has to be split up into a block of 2^n and a block of 1. It can only effect users of the block API, since the frame APIs will limit the block sizes correctly. *Technically* it is an incorrect usage of the block API, but the behavior is surprising, since the user already checked that the size is less than 128 KiB.

* I will fix the bug in the ZSTD_adjustCParams() function.
* I will also change the block compression API to return an error code if the source size is too large, which will make the API slightly more user friendly.

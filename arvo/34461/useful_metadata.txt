"The root cause here appears to be that both xmlAddNextSibling() and xmlAddChild() may optionally free their second argument (the `tmp` xmlNodePtr passed in) and return a different xmlNodePtr, or these functions may not free `tmp` and return the same pointer value.

In a nutshell, any code that ignores the return value of xmlAddNextSibling() or xmlAddChild()—and tries to use their second argument after they're called—could have the same use-after-free bug found in the attached test case.

I see various functions in tree.c, xinclude.c and xpointer.c could all potentially have this same bug."
